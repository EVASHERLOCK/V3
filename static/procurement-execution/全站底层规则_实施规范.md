# 药企采购执行｜全站强制底层规则（实施规范）

> 本原型为 DEMO / Non-GxP。正式上线需要通过企业数据治理、适用法规评估、验证与权限批准。**不能把本原型的“确认”或“已批准”代替 GMP、质量或财务的正式批准。**

## A. 每个小模块必须拥有完整的指标/文字分析血缘

- 每个小模块统一挂载 `∑ 计算血缘 / 分析规则` 和 `? 变量字典`，不能显示空白的“待登记”。
- **KPI**：列出唯一 `metric_id`、指标名称、指标归属、范围、单位、时间粒度、事实源表、关联键、输入字段、逐行派生公式、最终聚合公式、阈值、计算时点、缺失值处理、有效期与审批版本。
- **复合 KPI**：逐一列出每一个底层 KPI（如 PPV 和 OTD）的定义与公式，之后才列综合分析公式，避免黑箱“加权分”。
- **趋势、排行、散点、分布**：说明分组变量、分子分母、时间窗口、汇总公式、缺失月份、重复事件去重、过滤条件和展示阈值。
- **战略、根因、风险、行动等文字分析**：顺序固定为 **原始数据 → 数值计算 → 分维度拆解 → 交叉证据验证 → 候选解释 → 建议行动 → 责任部门复核**。不得无依据声称确定根因。
- 任一规则、变量或数据源缺失，页面应明确显示**待接入/待配置/不能计算**，不能用零值、模拟值或经验值覆盖。

## B. 每个小模块左下方必须提供“全量计算依据和来源表”及可下载 Excel

- 左下方 `▣ 展开全量计算依据和来源表` 显示所有相关源记录、输入字段、派生计算列与明细关联键。
- `↓ 下载本模块带公式 Excel` 下载**该模块独立工作簿**，不能下载空表；本原型为 8 页面 × 6 小模块 = **48 个 Excel**。
- 工作簿至少包含 `参数`、`原始与派生数据`、`指标计算`、`本模块计算`、`血缘与分析规则`、`变量字典`、`人工复核登记` 七个工作表。
- 计算单元格保留真实 Excel 公式（并在旁边提供可见公式文本），逐行派生列不是硬编码为汇总结果；允许修改源输入后重新计算。
- 页面筛选变化时，页面上的指标实时基于当前记录计算；默认下载完整可审核的演示数据集。生产版可加“按当前筛选生成”导出接口，必须把筛选条件写进参数表。
- 对于无法获得的真实 ERP/QMS/文件，必须标记 DEMO，不能虚构文件引用或完整审计链。

## C. 每个小模块右上方 `?` 展示完备变量

- 覆盖**所有原始字段 + 公式依赖的派生字段 + 分组字段 + 阈值参数**，不只显示当前可见 KPI 卡片的几个字段。
- 每个变量含：字段键、中文名、数据类型、单位、事实源、用途、是否派生、公式/血缘、缺失处理。
- 当上传文档提取字段时，额外显示文件名、版本、页码/表格单元格/EDI 段、解析方法、置信度、人工复核人员及时间。

## D. 采购执行的八个子页面

1. 合同核查：合同与 PO 的价格、数量、付款条件、Incoterms、有效来源与期限。
2. PO 创建与比对：PR→PO→供应商确认，多轮版本/交期/数量/价格差异。
3. 发运与到货：ASN、ETA、运单、GR、温控、CoA；不改写质量放行。
4. 发票核对：2/3/4 单匹配、疑似重复、差异调查，按企业实际规则判断付款条件。
5. 付款与应付：采购/AP 协同、账龄、冻结、贷项和付款状态，不替代财务支付权限。
6. 退货与索赔：RMA、质量事实源关联、补货、索赔、贷项/回款。
7. 订单关闭：收货、质量、财务、待办和受控关闭条件。
8. 跨流程异常：共享 case_id，自动核对→标记差异→分配负责人→上传证据→必要审批→重新核对→关闭。

## E. 数据字典、文件接入和生产环境接口

- 前端离线原型：**可解析基础 CSV、JSON、EDI 段**；PDF/图片/Excel 现在登记文件及待解析状态，不冒称已 OCR 或已连接 ERP。
- 生产建议：`POST /api/documents/upload`、`POST /api/documents/parse`、`GET /api/documents/{id}/extracted-fields`、`POST /api/documents/{id}/human-reviews`、`POST /api/matches/recalculate`、`POST /api/exceptions/{id}/submit-approval`、`POST /api/exceptions/{id}/close`。
- 文件证据字段：`file_id, filename, version, sha256, mime, received_at, source_system, page_or_cell, bbox_or_edi_segment, extraction_engine_version, confidence, value_before_review, value_after_review, reviewer_id, reviewed_at, reason, audit_event_id`。
- 匹配规则字段：`rule_id, version, source_ids, join_keys, comparison_fields, unit_currency_conversion, tolerance, result, variance, risk, human_override_reason, recheck_id`。
- 审计日志为 **append-only**，必须与企业 SSO、RBAC、QMS/ERP 适用权限管理、记录保留及验证程序集成。
- 与现有原材料生命周期的 `GR / 批次 / QC 检验 / QA 放行` 使用**只读事实接口**，不建设第二套质量放行数据。
- 与供应商合规、Change Control 和 Global/Local RA 对接的是**来源可用性、市场实施许可及异常约束状态**，不可将其简化成单一布尔合规结果。

## 执行新规则 D：询价（RFQ）报价比价与来源资格分离（新增第九页）

1. 新增 `00_询价与报价比对.html`，采用与采购执行其余八页相同的全站审计组件。
2. 每条报价保留 RFQ、PR、报价 ID、报价版本、币种、汇率日期、MOQ、数量、交期、有效期、价格以及运保税冷链估算，明细中的所有派生数值必须使用可见 Excel 公式。
3. 价格比较只在相同 RFQ、技术规格、工厂和适用市场下进行；先做源文件有效性、技术可比性，再判断质量和市场实施条件，最后对候选报价的到岸单位成本排序。
4. 低价不等于供应商已获批准，合格报价不等于有权采购。系统不可将 RFQ 比价结果自动批准为商业采购、质量放行或市场监管许可。
5. 分组价格和所有文字评审应能回溯到报价版本、原始文件、页码/单元格、人工确认、口径和计算规则；金额敞口不可与正式采购金额相加。
6. 报价数据跨合同、PO、财务、供应商合规、Change Control、RA 模块建立关联，但仅维护其引用记录，不替代其他系统的批准权限。
7. 询价页面的自动核对、差异、负责人、证据、审批、重核对和关闭均接入统一异常逻辑；离线演示不提供正式审批和自动关单。
