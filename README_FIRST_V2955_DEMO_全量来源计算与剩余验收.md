# V2.9.55 — 仅使用现有模拟数据的全量计算、来源与 XLSX 修复

## 目标和范围
- 本版继续以仓库内 23 份模拟 CSV（21,455 行）为唯一数据来源，不要求 ERP/QMS 或企业签名。
- 继续沿用 585 项原验收登记：217 个历史组件、306 个绩效中心入口、62 个采购执行模块。
- 这次不把“有公式单元格”“按钮能点击”直接认定为业务计算正确。

## 本轮实际完成及边界
1. **115 项 KPI，全范围来源与独立数值核验**：基于 1,440 条 `metric_events` 及其 PO、QC、库存、生产、供应商/主数据关联，独立重算 115/115 一致、字段关联差异 0。每项完整来源主键集合见 `docs/V2955_115KPI_全量来源主键与独立复算.json`。这些结果是 *模拟数据的来源和数字检查*，不是逐页面截图核验。
2. **九个执行页，全范围来源与计算检查**：覆盖 62 个执行模块、13,723 条页面来源记录，按对应真实 CSV 主键复核并独立重算 56/56 个聚合值。见 `docs/V2955_9执行页62组件_全量主键与算式核验.json`。同时修复合同、发票、付款、索赔、异常页面以前误用关联 PO ID 作为来源记录主键的问题。
3. **绩效中心 XLSX 公式修复**：原导出中的去重、预测误差以及 Top5 集中度在独立计算引擎中存在 10 项不一致；已改成逐行辅助公式，在供应商筛选样本独立重新计算得到 115/115 MATCH。新版 *全量 1,440 事件* XLSX 也已生成，带真实公式与原始来源，但因本运行环境的公式计算引擎资源限制，**尚未完成该大工作簿的第三方独立复算**，不得声称全范围 Excel 115/115 MATCH。
4. **585 项登记**：306 个绩效入口关联 KPI 的全来源主键；62 个执行入口关联全来源主键。217 个历史组件保留旧版三入口点击证据，但是其旧 V08 模拟数据与当前 23 份 CSV 的指标口径尚未逐项迁移，不能直接冒认当前数据的全量来源证据。
5. **自动化防误判**：`npm run check:v2955:source-and-calc` 对全来源、独立数值及汇总严格检查；`npm run check:v2955:strict` 仍会因全范围网页逐格对比、完整范围 Excel 第三方重算、历史数据口径及文字结论的语义核验不足而拒绝 585 项全通过。
