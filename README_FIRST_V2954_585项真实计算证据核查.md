- 检查每个组件是否具备：来源主键全集、独立计算器、页面可见数值同值、Excel 对应公式重算、文字分析条件核验。**严格验收仍不能通过。**

## 本轮发现的关键缺口

从保存的 217 项历史组件证据中，只有 **14 个组件有指标级来源主键样本**。一共检查 **576 条原始主键样本**：**147 条**能在目前 23 份 CSV 中按主键和已声明维度匹配，**429 条**找不到对应记录；这可能是不同批次的旧 Demo 数据口径造成，但**不能自动认定它们是当前来源表的有效记录**。即使 147 条主键一致，也仍需确认全量筛选范围和记录内容；不能视为组件全部来源已经复核。

585 项登记的完整逐格网页/Excel 对账没有对应的原始网页数值快照和重算证据，文字结论也没有完整逐条语义复核证据。**完整业务通过：0/585**。这不是 585 项都算错，而是证据未满足原定验收要求。

## 新增自动化命令

- `npm run check:v2954:business` — 产生证据细目和逐组件 CSV；若原始清单和 23 份 CSV 的完整性变动则报错。
- `npm run check:v2954:business:strict` — 585 项未全满足时返回非零退出码，不允许误放行。
- `npm run build` — 构建时运行上述普通证据扫描，但不以“尚未全部业务签核”阻止网站正常构建。
