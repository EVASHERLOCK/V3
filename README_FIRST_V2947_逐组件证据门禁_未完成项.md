# V2.9.47 逐组件验收继续推进（未取得全站业务放行）

本次从 V2.9.46 源码继续修改，不声明已经修复217个历史模块和14个iframe页面的全部计算链。V2.9.46 的接口/模拟数据检查仍属于数据层回归，不等于真实浏览器全量验收。

## 已交付源码改进

1. 新建 `docs/V2947_逐组件验收证据登记.json`：逐项登记旧基线217个历史组件；另外对5个绩效iframe和9个执行iframe登记74个**暂定子模块验收单元**。这些是页面级子模块类别，不等于所有实际渲染卡片已完成清点。原始基线有重复组件ID，登记时添加后缀保留其各自历史条目。
2. 新建 `scripts/check_v2947_component_evidence.mjs`：逐组件要求公式按钮点击、完整变量、计算条件、来源行身份与总行数、全量分页、网页单元格公式、XLSX单元格公式、Excel数值一致、文字解释步骤、真实浏览器端到端、业务签核十二类证据。任何组件标记PASS都必须同时具备十二类真实证据记录及可访问的本地证据材料路径，否则脚本直接报错；新增iframe路由缺登记也会失败。
3. 接入 `npm run check:governance`，增加 `npm run check:component:evidence` 及 `npm run check:component:evidence:strict`。非strict用于审计和生成待办；strict会在没有全量证据时非零退出，不能将未完成冒充验收通过。
4. 历史模块DOM采集结构显式添加 `captured_row_count`、`source_scope: VISIBLE_DOM_ONLY`、`full_database_verified: false`；网页来源行标题明确标示DOM行数不是数据库总数。**没有取消800行上限，也没有虚构数据库全量API。**
5. `docs/V2947_严格验收待办.json` 自动输出每个组件缺失的证据类别。

## 验证事实

- 当前登记291个验收单元：217个历史活动组件+74个iframe暂定子模块。具备完整十二类证据的数量仍为0。该数字只表示证据登记完成度，不等于功能全部失效。
- `npm run build` 通过；`npm run check:governance` 通过；`node scripts/check_v2947_component_evidence.mjs --strict` **预期失败（退出码2）**。
- 尝试本地Chromium访问Node HTTP页面未成功取得有效DOM；不能据此确认任何页面浏览器端到端通过。
- 尚未完成九页采购执行和五页绩效中心的逐格Excel和页面核对；不能把已有九份Excel可生成的结果当成逐格一致性证据。
