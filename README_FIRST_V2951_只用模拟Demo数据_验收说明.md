# V2.9.51 — 只使用现有模拟数据完成 Demo 验收（请先阅读）

## 关键纠正

本网站是 **模拟采购 Demo**，不是与企业 ERP/QMS 对接的生产系统。V2.9.50 将企业真实来源、正式 HTTPS 部署、企业数据负责人及业务负责人签名作为所有控件的正式验收硬门槛，**不符合当前项目目标**。V2.9.51 将它们从日常 Demo 构建/验收流程移除；原企业级脚本仅保留为日后真正需要上线时的可选工具。

**在 Demo 模式下，无需提供 ERP、QMS、真实数据库、真实采购记录或企业负责人签字。** 本项目应依据自己的模拟数据完整性、页面操作、Excel 真实计算公式和说明质量验收。

## 本轮实际核查

- `seed_simulated` 下**23 份 CSV、21,455 行模拟数据**逐文件读取、哈希和主键唯一性检查，其中 21 张规范业务表、2 份辅助数据（供应商受控文件台账 80 行、月度 KPI 汇总 12 行）。21 张业务表的原有分页快照测试已通过，另外 2 份按完整 CSV 全量读取，不谎称通过相同的 API 分页。
- 21 张规范表的跨表引用和业务约束检查：0 处违规；辅助供应商文件 80 行的供应商/物料/项目引用检查通过。
- 12 个月 KPI 汇总按采购订单、发票和付款明细独立重算（月采购支出、OTD、足量交付、开票金额、已结清付款金额），通过。两份辅助 CSV 过去不在“21 表”核查口径内，本轮已补入。
- 保留既有“115/115 KPI MATCH”和“九个采购执行页面指定筛选样本 1,512 项逐格 MATCH”复算证据。这些证据来自此前独立测试，并不意味着当前已经重新测试全部筛选组合。

## 执行方式

从项目根目录执行：

```bash
npm run build
npm run check:v2951:demo
```

Demo 的机器结果：`docs/V2951_Demo_验收报告.json`；逐项清单：`docs/V2951_Demo_585项验收进度.csv`；23 份来源文件的哈希/主键/行数登记：`docs/V2951_Demo_全量来源清单.json`。静态站点新增可视化页面 `/static/audit/demo-acceptance.html`（会随着构建发布）。

在允许浏览器访问本机 HTTP 的电脑上，启动 Node 预览后可执行浏览器点击检查：

```bash
npm run dev
# 在另一个终端：
python3 scripts/browser_v2951_demo.py --url http://127.0.0.1:3000 --scope all
npm run check:v2951:demo
```

运行该检查需要 Playwright/Chromium。`--url` 应替换为**你实际启动的网站地址**；3000 只是示例，本项目实际端口应按服务启动日志为准。这个检查允许 localhost，不要求企业 HTTPS，不要求 ERP。它尝试逐个点击并下载含公式的 Excel；本次已按 `--scope legacy` 尝试实测，首个 HTTP 页面被管理员策略阻止，剩余 216 项未执行，因此本包**没有伪造 217 项浏览器点击 PASS**。

`npm run check:v2951:demo:strict` 是 Demo **全站最终放行门禁**：只有 585 项逐组件证据完成后才会返回 0；当前预计返回非零，这是诚实的未完成提示。与企业级脚本是否存在无关。
