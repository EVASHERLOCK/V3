# V2.9.25 全站 26 页指标与组件级血缘验收清单

> 2026-11-08。**这是覆盖与缺口报告，不能作为生产 GxP 批准。** 当前以 V2.9.24 为基线，新增全站企业来源**替代**视图。没有把 26 页原有所有 DEMO 专有图表的计算代码替换掉。

## 验收总体结果

- **77 个来源计算指标定义**、**18 类可复核确定性文字分析规则**，可生成带原始行和 Excel 公式的工作簿。工作簿专项测试检测到 **221 个公式单元格**，不代表 221 个独立指标。
- **26 个页面、179 条页面到指标映射**；同一指标出现在多页。指标目录并非对页面全部数字的百分百覆盖。
- 所有 26 页面都新增一致的 **企业模式统一看板**，从同一已审核发布快照读取采购 PO 与 QMS 事件，生成采购 Spend 分供应商、物料、月度分组、OTD × PPV 和 QMS 事件图。
- 图表可展开到每个分组的源 PO / QMS 行：ID、供应商、物料、数量、单价、金额、延期，以及计算说明；另有逐指标弹窗与 Excel 下载。
- 每页跨源对账检查：供应商/物料/月度金额之和 = 原始 PO 金额 = 来源 Spend 指标，PO/QMS 主键不能重复；检查快照内容 SHA-256、审计哈希链。校验失败或快照撤回返回 409，不回退 DEMO。
- 企业模式每 15 秒向 Node 检查快照指纹以刷新。**这里的 15 秒是前端检查频率，不是 ERP/QMS 实际采集频率。** 没有持久化 Node 或网络时不能保证实时。
- 仍缺逐个迁移旧版所有图表、复杂评分、风险预测、文字根因等专属计算逻辑。演示模式下未绑定组件显式显示 **“逐组件血缘待登记”**，并有覆盖检查表。

## 数据口径与防误报

- 原站保留 **24 行 DEMO PO、3 个原站 DEMO 供应商、77 家扩展情景候选**，仅作为演示来源。77 家情景候选不贡献正式 Spend，也不会被直接认定 GMP/CEP/ASL 合格。
- 企业模式与演示模式按 UI 强制隔离，**企业快照缺少合同、供应商正式资质、库存等记录时数值显示不可计算**。不混入 DEMO 金额。
- 发布快照只代表管理员确认其可用于分析，**不是**受控电子签名、QA 放行、ASL 准入或生产系统写回。
- FDA/EDQM 官方公共数据与私有企业 ERP/QMS 是不同来源；公开网页、官方名单和 CEP 文本记录也不能直接当作正式企业资格批准。

## 继续整改门槛

1. 逐组件登记 DOM/业务指标唯一 ID，连接当前实际参数、数据源、输入行和 Excel 公式。当前通用组件扫描只提示缺口，不算完成迁移。
2. 每页遗留原版业务特色图表（甘特、BOM瀑布、供应商级别、CAPA、监管资格等）按同一企业快照逐个重写，并验证缺数据时明确展示状态。
3. 企业服务器对接真实 ERP/QMS API 后运行同源金额、数目、分组及外部总账对账；增加身份认证、快照审核策略和审计防篡改验证。
4. 真实 FDA/EDQM 在线监测需在具有外网与许可的持久化环境进行；采集成功数量、时间、哈希和误差应留审计记录。
