# V2.9.28 全站最高优先级规则：模块指标及文字分析血缘

本规则与全站 Top10 排序并行，不能由帮助提示、空白指标目录、占位按钮或空工作簿替代。

## 规则 A — 逐模块计算与分析透明性

每个有业务图表、KPI、表格或文字结论的业务模块，在右上方提供“∑ 本模块公式 / 分析依据”。
必须保留模块唯一标识、当前筛选条件、各基础指标独立 ID、输入行、计量单位、分子、分母、权重、公式及来源类型。
复合矩阵（OTD × PPV）必须分别列出 OTD 和 PPV，交叉坐标不当作乘积。
文字行动/根因必须先展示计算结果、阈值和原始行，再展示确定性规则、建议结论和不能证明的因果缺口；不得公开声称已证实的事故根因或 AI 私密推理。

## 规则 B — 逐模块全量计算依据和 Excel 真公式

每个模块左下方提供“▤ 展开全量计算依据和来源表”和“↓ Excel 含真实公式”。
导出内容必须包括本模块标题/ID、来源等级、当前筛选范围、服务端指标公式表、PO/QMS等来源输入、模块全部当前呈现的表格、计算和文字建议的步骤、证据缺口。
对具备明确数量×单价或评分×权重字段的表格，增加真正 Excel `<f>` 公式；统一公式工作簿保留原 PO、QMS、资格及其他输入和来源计算公式。
仅 DOM 显示值而非受控业务来源时必须标明“UI 展示快照、不可证明正式原始证据”；对于当前没有足够来源的指标明确拒绝伪造公式与结果，禁止生成“空而不说明原因”的文件。

## 审计验收边界

模块级数据导出不是 ERP/QMS/GxP 受控电子记录；未发布的正式企业数据不能通过 DEMO 回退，所有企业数据详情/Excel 访问需验证快照完整性及服务端授权。没有现成正式来源的复杂专用图表，其逐行业务公式仍需要采购/质量/法规专业负责人审批和真实企业数据验证；不会把通用来源表解释为它已达到 GxP 审计级。


## V2.9.29 再加强：全站扫描与三层验收

- `scripts/check_component_lineage_v2929.mjs` 基于26个路由、242个已观察模块的隔离浏览器清单，严格分开：①业务计算/判断方法已匹配；②操作控件没有独立业务公式；③来源行仍需企业核验。
