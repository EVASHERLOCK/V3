# Pharma AI — 全站问号与完整业务分类字典（永久强制设计规则）

**状态：不可删的产品基线 / Non-negotiable**  | 生效：V2.9  | 范围：全部业务模块（含未来新增）、图表、表格、指标、筛选器与控制中心。

## 强制规则

1. **全覆盖**：每个页面、可识别的业务卡片、KPI、图表、表格、筛选器都在该模块右上角展示可点击 / 键盘操作的 `?`。允许页面重新排版，但不允许去掉问号。新建模块应有可识别标题，自动注入并通过本页覆盖率审计。
2. **完整分类独立于当前数据**：点击问号打开该主题的完整参考分类、根因、问题类型、建议、预期效果、状态和业务口径。不管筛选后只出现多少种，词典不能缩减、删除未命中类型或只显示“存在数据”的选项。词典支持未来按企业 SOP、权限与主数据版本扩充，但不得静默删减既有类目。
3. **明确区分参考与真实**：帮助抽屉的“本模块可见”仅是当前页面文字匹配，不代表数据已被审计或正式确认。未显示的类别可能是无记录、未配置、字段缺失或筛选排除，不应暗示不存在。避免把参考行动或预测收益直接显示成真实执行记录。
4. **来源与计算**：模块说明应提示数据来源、筛选口径、计算公式/分子分母、适用范围、风险等级、责任部门、明细和审批边界。没有足够依据的内容必须显示“未接入/待核验”，不应编造。
5. **GMP/法规边界**：帮助字典只是排查参考，不代替正式受控程序、QA/RA 决策、GMP 放行或有效注册状态。
6. **可维护、可验收**：中心脚本 `static/global_help.js` 负责自动注入和 `window.PharmaGlobalHelp.audit()`；样式文件 `static/global_help.css`；静态字典 `GROUPS` 与页面路由分类 `ROUTES`；未来新增专属分类要在这些源文件中补充。
7. **自动检查不可移除**：所有 `npm run build`、`npm run dev`、`npm test`、`npm run check:files` 必须先运行 `node scripts/check_global_help.mjs`。若词典文件、内嵌脚本、样式、路由覆盖、核心分类或文档缺失，**构建必须失败**，不能默默上线缺少帮助机制的版本。
8. **浏览器验收**：在每个页面用 `window.PharmaGlobalHelp.audit()` 检查 `modulesWithHelp===modules` 且 `filtersWithHelp===filters`，点击至少一个风险根因、一个预算/行动模块以及一个筛选器中的 `?`，观察抽屉是否同时列出当前页面识别项和完整预置类别。

## 字典的维护方式

- `GROUPS` 中每一类包括 `title/description/items`；内容是药企采购参考分类集合，企业实际使用前须进一步按照 SOP 分类编码和主数据确认。
- `ROUTES` 为每个页面给出默认完整词典类别，`MATCHERS` 用模块中文/英文标题匹配更具体的词典。
- 对新增模块无需复制弹窗代码，但应写有准确标题，并按需要扩充分类；未匹配标题仍显示所在页面的默认完整字典，而不是缺失问号。
- 统计当前命中只基于当前模块可见文字，**绝不能把其数量用于 KPI 或分析模型统计**。所有 KPI 继续从原始统一数据模型计算。
- 应允许 `?` 以键盘 Enter/空格打开，Escape 关闭，帮助抽屉可独立滚动。不要改变原业务按钮的点击行为。

## 重要示例：风险根因分布

即使当前明细只包含“库存不足”“供应商延期”，`?` 仍应展示需求预测、销售波动、排产变更、紧急插单、MOQ/LT、安全库存设置、QC/放行、GMP/注册、主数据、运输清关、合同价格、审批流程、系统接口等**完整可能根因**。其中“当前页面没有出现”不是“根因不存在”，应继续核查证据。

## 发布说明

当前项目是 DEMO / Non-GxP 原型，词典是参考性知识库，不是法律或监管要求的封闭清单。上线生产环境需审批正式分类字典版本、责任人及审计记录。目录不受当前数据量限制，但其覆盖度应由业务负责人持续评估并扩充。
