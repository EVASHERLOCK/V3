# 全站最高优先级、不可回退规则（V2.9.45）

> 本文件是项目内的**强制实施契约**，优先于旧版网页模板、旧版审核说明、静态演示兜底以及 UI 视觉要求。新增网页、修改网页、数据迁移、接口变更、Bolt 发布都必须执行。不能以自动化测试“可运行”代替逐项业务验收。

## A. 每个小模块右上角：∑ 本模块公式 / 分析依据

1. 每一可展示 KPI、图表数据系列、表格派生字段、评分/排名及报警结果都须给出：唯一稳定 ID、变量中文解释/英文缩写、数据表和记录级主键、单位/币种、统计时点、筛选范围、去重方式、分子分母、权重、阈值、完整公式、结果、版本、来源等级、异常边界。复合指标必须将上游指标逐个拆解，不可只列最后一步。
2. 文字分析、战略建议、根因与行动决策必须严格依次呈现 **源数据 → 派生指标 → 对比基准 → 维度拆解 → 业务规则/条件 → 有条件结论 → 人工审批边界**；应披露该模块所用全部术语、专业缩写、变量及分析步骤，不得写不依赖数据的泛泛套话，不得声称无证据的因果关系。
3. 若业务公式、来源数据、目标或审批证据确实没有登记，必须明确列为 `NOT_VERIFIED`/`SOURCE_MISSING`；不得借用不相干指标替代、不得将无记录视作 0，也不得声称本模块已通过。

## B. 每个小模块下方：▤ 展开全量计算依据和来源表

1. 以**可查看、可筛选、可定位记录/单元格的明细表**为正文，至少包含原始输入、变量定义、按业务键关联明细、派生/聚合计算列、每行 Excel 单元格坐标与**具体公式文本**、逐步演算值、分子分母及结论解释。
2. 页面源行有分页/截断时必须提示“当前显示 X/Y 行”，并提供相同筛选口径的全部源行获取方法，不得把 800 行 DOM 截图称为数据库全量。展示层数值与数据库来源行、模拟数据与受控企业数据必须分级区分。
3. 针对文字结论也须先提供指标数据和阈值表，再提供每一步文字分析与建议，注明规则 ID、责任角色和审核边界。没有源数据的风险/战略不能凭文案冒充事实。

## C. 每个小模块下方：↓ Excel 含真实公式

1. 按当前模块和筛选条件导出真正的 XLSX（不以 CSV、公式字符串或只有结果的静态 Excel 冒充）；包括完整输入数据、主键关系、参数/权重、派生字段每行 `<f>` 真公式、聚合公式、指标解释、术语字典、逐格公式索引、逐步文字解读、结论条件及数据证据等级。表内公式坐标、公式文本、计算结果必须与网页一致。
2. 预览 Node 与静态发布都需测试。静态模式无法重算的指标必须注明边界，不得沿用筛选前数值；企业授权/真实电子签名和审批绝不能由 DEMO 替代。
3. 下载必须在实际浏览器中检查响应格式、公式单元格数量、来源明细数量以及至少一个计算例子的网页-Excel 一致性。

## D. 全站一致性 / 门禁

- 适用：所有导航入口，**包含独立 iframe 的 5 页绩效中心、9 页采购执行、统一数据中心，以及 Change Control 专用页面**；不能因 iframe 或 CSS 排除扫描就宣布全站完成。
- 一切修改前须更新路由清单、模块/表格/图表/文字分析登记；修改后运行 `npm run check:governance`、项目原测试、构建、至少一项真正点击三个入口的浏览器测试与可复算 Excel 验证。新路由必须自动纳入登记；漏登记应阻止构建。
- `npm run check:governance:strict` 是**全站正式验收门槛**：有未验证模块时它理应失败；不可把该失败隐藏成 PASS。代码检查通过只证明规则未被删除，不证明业务计算已覆盖。
- 全站公式、指标、数据源、单位和筛选范围应共享业务主键（supplier_id/material_id/project_id/PO_id）。跨页面同名指标应由同一规则版本复算；不能用与其业务无关的默认 PO/QMS 行填充空表。
- 强制保留模拟 / 企业验证证据的显著区分：`SIMULATED` 仅为演示；不等于 GxP、财务、QA 或 RA 正式签核。允许没有匹配业务记录的真实空结果，禁止造数据来隐藏缺口。
- 针对每个后续版本，交付必须包含：逐页路由覆盖清单、逐模块公式/数据/Excel/文字解读核验清单、失败项目、测试环境和上线前待核对项目。不得笼统宣称“没有一处遗漏”。
