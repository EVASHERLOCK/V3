# Pharma Procurement AI V2.9.43 — 采购执行管理九页面全关联模拟数据与发布修复

> **仅用于演示/测试（SIMULATED / 非 GxP）。** 所有供应商、金额、签署、文件、审批和支付记录都是按规则生成的模拟事实，绝不是企业 ERP/QMS/AP/银行凭证。任何页面数值不构成真实业务建议。

## 本次修复的关键问题

原 V2.9.42 的 9 页虽然 Preview 的 Node 服务可以读取模拟种子数据库，但 `build_static.mjs` 在导出 `static/procurement-execution/site-data.js` 时**过早使用了默认 LEGACY_DEMO 数据**，导致静态发布仍会出现合同、发票、付款等页面空白。V2.9.43 修复了构建时的数据模式顺序，现有 `npm run build` 默认导出 `SIMULATED` 的九页面全量数据快照；`dev:legacy` 仍可显式采用原始演示数据用于回归。

## 数据规模与关系

- 80 供应商、120 物料、24 项目、30 产品线；覆盖 **2025-11 至 2026-10 共 12 个月**。
- 1,440 采购需求/订单、1,440 授标报价、**2,880** 未授标备选报价，共 **4,320 询价报价行**；按同一个 RFQ 可以比较三个不同供应商。

- 模拟信用证/支付授权、合同签署、质量状态只作为合成事件，不会标注为生产环境真实批准。

## 口径与改动

- 采购订单、收货、发票与支付逐笔核对：收货数量→已开票数量→已确认应付→实际模拟支付→未付余额。逾期账款以未付余额及到期日判断，不把未付款视作已完成支付。
- 索赔通过 `claims` × `claim_settlements` 关联；未结索赔不会因为存在索赔金额就被当成已追回。
- 关单必须同时检查未收货、质量待放行、未付余额、未结索赔及未关闭异常。
- `project_id` 与供应商、物料、月份筛选器在九个页面统一联动。下钻与 Excel 使用同一筛选范围。
- `跨流程PO关联与余额` Excel 标签页按 PO 连接 RFQ、合同、QC、发票、付款、索赔、异常，含实际 Excel 公式单元格。
- 原来的 65 个参考 Excel 与 9 个 HTML 模板保留。

## 使用与重新发布

1. 解压本 ZIP 到 GitHub/Bolt **项目根目录**；不要另外上传 `dist/`、重新生成的 `seed_simulated/*.csv` 或原型单独数据包，否则很容易超过 Bolt 7.8 MB 文本导入限制。
2. 在 Bolt Terminal 执行：

```bash
npm install
npm run build
npm run check:execution:full
node test_v2943_static_publish.mjs
npm run dev
```

3. Preview 打开 `#exec-00` 至 `#exec-08`；在 02、04、05、07 页面按同一供应商/物料/项目/月份筛选后查看 PO 主键与金额。
4. **点击 Publish → Update 更新线上静态网站**。`npm run build` 会把压缩模拟 CSV 还原并生成正式发布的 `dist/static/procurement-execution/site-data.js`（约 12MB，属于生成产物，不上传 GitHub）。如果没有执行 build，旧站可能仍读取前一版本的 DEMO 快照。
5. 若需对真实企业数据进行持久化修改、审核与动态 Excel 下载，仍需部署 `server.mjs` 到有受控权限的 Node 后端。静态发布的合成数据库不具备真实 SAP/QMS/银行连接。
