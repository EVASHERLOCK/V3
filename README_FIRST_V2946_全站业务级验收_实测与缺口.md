# V2.9.46 全站业务级复核（真实状态：尚未全面放行）

本包是在 V2.9.45 上增加可重复执行的**业务数据验收、逐页/逐组件结果清单、CI持续检查及严格发布门禁**。本次没有对未实测的页面进行虚假通过标记，也没有更动采购UI模板/计算公式/模拟业务事实。

## 可验证的结果

运行 `npm run build && npm run check:business:all` 可复核：39个现行路由登记；115/115项绩效模拟KPI和12个月计算；静态绩效快照115/115与Node同值；9页采购执行、56/56项模拟KPI；9/9份按选定来源生成的XLSX文件；1440/1440条PO→发运→发票→付款→关单金额/数量链；模拟数据库外键违规0项。

这些数值仅为**SIMULATED**数据的业务契约验收，不等于企业ERP/QMS/RA实证。

## 仍未通过的业务级验收

- 历史组件基线共有217个活动组件。静态历史快照中116个包含三入口文字、101个缺少至少一个入口文字。但**文字存在不代表真实按钮可用**，所有组件仍须浏览器逐个点击并核对同一来源行的公式。
- 绩效中心5个iframe、采购执行9个iframe有自身独立功能与报表，但无法仅凭Node接口的计算通过证明每张卡/图/表满足管理层统一三入口。
- 通用全量来源当前采集DOM可见行存在800行上限；必须在单模块按来源表+当前筛选导出全量明细时核实记录数，不能称页面中的可见片段为“全量”。
- 模拟数据接口已复算，但本环境的Chromium在访问本地HTTP网页时返回`ERR_BLOCKED_BY_ADMINISTRATOR`；因此39页真实浏览器端到端与正式Bolt发布态未能完成确认。
- Excel 9/9表示九个采购执行页面**各成功生成格式有效的XLSX**，不代表逐单元格跨页公式均由Excel客户端复算通过。

```bash
npm run check:governance
npm run check:governance:strict
```
